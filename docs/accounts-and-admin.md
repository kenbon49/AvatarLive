# 账号、审批与配置部署

迁移到最新版本后，在 API 所连接的数据库上运行 `python3 -m app.bootstrap_admin`。
命令会交互式读取管理员邮箱和密码；首次创建时把原有无归属的直播间、商品与推流连接归给该管理员。
不要把管理员密码放进命令参数、仓库、日志或环境文件。
自动化部署可以使用 `--email 管理员邮箱 --credentials-file /仅管理员可访问的目录/初始凭据.txt`；
命令会生成随机密码并保存到新建的 `0600` 文件，绝不覆盖已有文件。初次登录后将密码转存到受控密码库并删除临时凭据文件。

本机的正式 API 是从仓库根目录加载 `.env` 的 systemd 服务。首次初始化必须使用相同配置：

```bash
cd /data/yangcheng/AvatarLive/apps/api
set -a
. ../../.env
set +a
python3 -m app.bootstrap_admin
```

确认管理员创建成功后再切换新版 API/前端；在此之前不要启动要求登录的新版正式服务。

普通用户在 `/register` 提交申请后处于待审核状态。管理员从 `/admin` 审核后，用户才能登录并操作自己的数据。
管理员自身的 LLM 和分镜合成调用不限积分，但调用次数、实际供应商成本和状态仍会记录。普通用户使用独立钱包，100 积分 = 1 元；数据库以整数微元保存金额，避免低价 Token 取整失真。
管理员分配积分时消耗独立的平台可分配资金池，不再读取或扣减管理员个人钱包。先在 /admin 用实际付款订单号或流水号确认入账，再向已审核的普通用户分配。阿里云账户余额仅用于监控和低余额提示，不会自动转换为平台资金或用户积分。
管理员可以从用户详情停用或恢复普通账户；停用时会立即撤销该用户的全部登录会话。积分管理支持增加、扣减和设定余额，扣减结果不能低于零，每次调整都必须填写原因。账户审核、快速分配、积分调整和状态变更都会记录操作人、时间、变更内容及原因，并在用户详情的操作审计中展示。
登录页支持管理员用户名或注册邮箱；普通用户仍使用注册邮箱登录。
生产环境应设置 `AUTH_COOKIE_SECURE=true`，通过 HTTPS 提供站点，并限制 API、数据库与媒体网关的公网访问。

## 成本结算

- 阿里云灵眸 `CreateBroadcastVideoFromTemplate` 先按文本与语速冻结预计积分；任务成功且 WebM 下载到本机后用 `ffprobe` 读取成片时长，按每秒 0.1 元（每分钟 600 积分）向上取整到秒结算。云端明确失败会释放冻结，本地下载失败不会被当作云端合成失败。
- DeepSeek 调用按返回的缓存命中输入、缓存未命中输入和输出 Token 分项结算。流式调用启用 `include_usage`。每条用量保存模型、价格版本、峰谷时段、上游成本和用户实扣金额。
- DeepSeek 默认价格来自官方人民币价目；当前 LiteLLM 网关没有余额查询接口，因此余额不伪装成“自动同步”。若网关合同价不同，必须通过 `LLM_PRICING_OVERRIDE_JSON` 配置实际合同价。
- `BILLING_MARKUP_BASIS_POINTS=10000` 表示按上游成本原价扣用户积分。可调整加价率和 `BILLING_MIN_CHARGE_MICROS`，上游成本与用户实扣仍会分开保存。
- 阿里云余额快照默认缓存 10 分钟，也可在用户列表顶部手动刷新。余额来自整个阿里云账户，只用于监控。

官方定价参考：

- 阿里云灵眸视频：https://help.aliyun.com/zh/avatar/avatar-application/product-overview/avatar-video-pricing
- DeepSeek API：https://api-docs.deepseek.com/zh-cn/quick_start/pricing

管理员页面里的业务 API 配置（Azure/LLM 等）可在 API 进程中生效。跨服务和基础设施参数只加密暂存。
在「账号与登录 → 系统设置」的大模型服务区填写 OpenAI 兼容的 HTTPS Base URL（含 `/v1`）和 API Key；保存时会先读取该服务的 `/models`，成功后才加密保存 URL/Key。模型列表由服务端实时获取，管理员从列表选择默认模型；脚本扩写、商品话术和直播问答会使用该默认模型。更换服务时如果旧模型不在新列表中，请先选定一个新模型再发起生成。模型目录可用只代表配置连通，不代表所有模型都支持图片或普通用户有可用积分。
基础设施状态仅表示 API 进程中能检测到参数，不代表数据库、媒体网关等已经连通，或 Next 等其他服务已经应用修改。
“已加密保存修改”表示数据库有一个管理端保存值；即使写入环境文件，也须核对 Compose 覆盖、重启服务并验证配置才算部署完成。
服务器根密钥 `PLATFORM_ENCRYPTION_KEY` 必须由部署环境安全保存，不在管理页面回显或直接覆写；
平台凭据主密钥可以在管理页轮换，轮换时必须没有未结束的直播任务，并会在单一数据库事务中重加密已有推流凭据。

部署人员使用 `python -m app.apply_staged_settings --env-file /明确路径/.env` 检查待应用项目；
核对环境文件和目标部署后加 `--apply` 写入。命令不会自动重启服务。
如 Compose 在 `environment:` 中覆盖某些变量（例如 `DATABASE_URL`），还需同步修改 Compose 配置并迁移数据，
单独更改 `.env` 不会切换现有数据库。应用后按部署流程重启 API/Next 服务，验证健康检查。
