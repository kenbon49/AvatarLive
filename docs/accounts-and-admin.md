# 账号、审批与配置部署

迁移到最新版本后，在 API 所连接的数据库上运行 `python3 -m app.bootstrap_admin`。
命令会交互式读取管理员邮箱和密码；首次创建时把原有无归属的直播间、商品与推流连接归给该管理员。
不要把管理员密码放进命令参数、仓库、日志或环境文件。
自动化部署可以使用 `--email 管理员邮箱 --credentials-file /仅管理员可访问的目录/初始凭据.txt`；
命令会生成随机密码并保存到新建的 `0600` 文件，绝不覆盖已有文件。初次登录后将密码转存到受控密码库并删除临时凭据文件。

本机的正式 API 是从仓库根目录加载 `.env` 的 systemd 服务。首次初始化必须使用相同配置：

```bash
cd /data/yangcheng/AvatarLive/apps/api
set -a
. ../../.env
set +a
python3 -m app.bootstrap_admin
```

确认管理员创建成功后再切换新版 API/前端；在此之前不要启动要求登录的新版正式服务。

普通用户在 `/register` 提交申请后处于待审核状态。管理员从 `/admin` 审核后，用户才能登录并操作自己的数据。
管理员自身的 LLM 和分镜合成调用不限额度且不扣减可分配余额，调用次数和状态仍会记录；普通用户继续按计费标准扣额度。管理员向普通用户分配额度仍需先按实际付款凭证充值入账。
登录页支持管理员用户名或注册邮箱；普通用户仍使用注册邮箱登录。
生产环境应设置 `AUTH_COOKIE_SECURE=true`，通过 HTTPS 提供站点，并限制 API、数据库与媒体网关的公网访问。

管理员页面里的业务 API 配置（Azure/LLM 等）可在 API 进程中生效。跨服务和基础设施参数只加密暂存。
在「账号与登录 → 系统设置」的大模型服务区填写 OpenAI 兼容的 HTTPS Base URL（含 `/v1`）和 API Key；保存时会先读取该服务的 `/models`，成功后才加密保存 URL/Key。模型列表由服务端实时获取，管理员从列表选择默认模型；脚本扩写、商品话术和直播问答会使用该默认模型。更换服务时如果旧模型不在新列表中，请先选定一个新模型再发起生成。模型目录可用只代表配置连通，不代表所有模型都支持图片或普通用户有可用额度。
基础设施状态仅表示 API 进程中能检测到参数，不代表数据库、媒体网关等已经连通，或 Next 等其他服务已经应用修改。
“已加密保存修改”表示数据库有一个管理端保存值；即使写入环境文件，也须核对 Compose 覆盖、重启服务并验证配置才算部署完成。
服务器根密钥 `PLATFORM_ENCRYPTION_KEY` 必须由部署环境安全保存，不在管理页面回显或直接覆写；
平台凭据主密钥可以在管理页轮换，轮换时必须没有未结束的直播任务，并会在单一数据库事务中重加密已有推流凭据。

部署人员使用 `python -m app.apply_staged_settings --env-file /明确路径/.env` 检查待应用项目；
核对环境文件和目标部署后加 `--apply` 写入。命令不会自动重启服务。
如 Compose 在 `environment:` 中覆盖某些变量（例如 `DATABASE_URL`），还需同步修改 Compose 配置并迁移数据，
单独更改 `.env` 不会切换现有数据库。应用后按部署流程重启 API/Next 服务，验证健康检查。
